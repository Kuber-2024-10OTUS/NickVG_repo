Helmfile — это инструмент для управления Helm-чартами, который позволяет автоматизировать процесс установки и обновления приложений в Kubernetes с использованием Helm. Он упрощает управление зависимостями между чартами, настройками значений и средами развертывания.

### Структура Helmfile

Файл helmfile.yaml является основным конфигурационным файлом, где определяются все необходимые параметры для работы с Helm-чартами. Вот пример структуры файла:

# helmfile.yaml
repositories:
  # Список репозиториев, откуда будут браться чарты
  - name: stable
    url: https://kubernetes-charts.storage.googleapis.com/
  - name: bitnami
    url: https://charts.bitnami.com/bitnami

releases:
  # Список релизов, которые нужно установить
  - name: nginx-ingress
    chart: stable/nginx-ingress
    version: "1.41.3"
    namespace: ingress-nginx
    values:
      - ingress-class: "nginx"
  
  - name: prometheus
    chart: stable/prometheus
    version: "14.0.4"
    namespace: monitoring
    values:
      - server.global.scrape_interval: 15s


### Разделы конфигурации

#### Репозитории (repositories)
Этот раздел определяет список репозиториев, откуда Helm будет брать чарты. Каждый репозиторий задается именем и URL-адресом.

Пример:
repositories:
  - name: stable
    url: https://kubernetes-charts.storage.googleapis.com/


#### Релизы (releases)
В этом разделе перечисляются релизы (установки чартов), которые необходимо выполнить. Для каждого релиза указывается имя, название чарта, версия, пространство имен и значения параметров.

Пример:
releases:
  - name: nginx-ingress
    chart: stable/nginx-ingress
    version: "1.41.3"
    namespace: ingress-nginx
    values:
      - ingress-class: "nginx"


#### Значения (values)
Значения позволяют переопределить настройки чарта. Они могут быть указаны либо в виде списка YAML-файлов, либо непосредственно в самом helmfile.yaml.

Пример:
values:
  - ingress-class: "nginx"


### Использование Helmfile

После того как файл helmfile.yaml создан, вы можете использовать следующие команды для выполнения различных операций:

#### Синхронизация всех релизов
Эта команда обновляет состояние всех релизов согласно вашему helmfile.yaml. Она устанавливает новые релизы, удаляет старые и применяет изменения к существующим.

helmfile sync


#### Установка конкретного релиза
Для установки определенного релиза можно указать его имя через параметр --selector.

helmfile --selector name=nginx-ingress apply


#### Удаление конкретного релиза
Удаление релиза также возможно с помощью параметра --selector.

helmfile --selector name=prometheus delete


#### Просмотр изменений перед применением
Чтобы увидеть, какие изменения будут внесены до их применения, используется команда diff.

helmfile diff


### Дополнительные возможности

#### Условная логика
Вы можете использовать условную логику для определения среды развертывания. Например, вы можете определить разные значения для разных пространств имен или кластеров.

environments:
  dev:
    values:
      - replicaCount: 1
  prod:
    values:
      - replicaCount: 3


#### Темплейты
Вы можете использовать Go-шаблоны для динамического создания частей helmfile.yaml, что особенно полезно при работе с большим количеством одинаковых релизов.

templates:
  - name: my-template
    selector: {name: "{{ .Release.Name }}"}
    releases:
      - name: {{ .Release.Name }}
        chart: stable/{{ .Chart.Name }}
        values:
          - image.tag: "{{ .Values.image.tag | default \"latest\" }}"


### Заключение

Helmfile значительно упрощает работу с Helm-чартами, позволяя централизованно управлять всеми установками и обновлениями приложений в Kubernetes. Он поддерживает различные сценарии использования, от простого развертывания одного приложения до сложных многоуровневых систем с различными окружениями и условиями.
